1. What gets installed

PartRuns onStatus
A. Navigation subsystemUbuntu 24.04 PC, ROS 2 Jazzy, Gazebo HarmonicBuilt and evaluated in simulation (Gazebo). Not yet run on the physical robot.
B. Trash detection subsystemPython 3 machine; benchmarked on a Jetson Orin NanoThree trained detectors (YOLOv8n, YOLOv11n-seg, RF-DETR) with demo and benchmark apps.
C. Manual modeRobot computer with a touchscreen + Arduino UnoImplemented on hardware. The firmware drives the two motors; vacuum, arm, wiper and UV commands are accepted as flags only.

The three parts are independent: each can be installed on its own.

2. Get the code

The model weights and map files are stored with Git LFS, so install it before cloning.

sudo apt install -y git git-lfs
git lfs install
git clone https://github.com/swachhbaudhikkayantra/Swachh.git ~/Swachh
cd ~/Swachh
git lfs pull                 # fetches model weights (.pt, .onnx, .trt) and .npz files

All paths below assume the repository is at ~/Swachh. Two folder names contain a space (Object Detection, Manual mode), so keep them in quotes.

4. Part A: Navigation subsystem (ROS 2 + Gazebo)

4.1 Requirements

ItemRequirement
Operating systemUbuntu 24.04 (needed by ROS 2 Jazzy)
ROS 2Jazzy (ros-jazzy-desktop, ros-dev-tools)
SimulatorGazebo Harmonic (gz-sim 8.x)
Mapping and navigationrtabmap_ros, Nav2 (with SmacPlannerHybrid), spatio-temporal-voxel-layer
MiddlewareCycloneDDS (rmw_cyclonedds_cpp)
Python3.12 with numpy, scipy, matplotlib, PIL, yaml, pytest, cv2
GPUOptional. NVIDIA driver 570+ recommended; without a GPU Gazebo uses slow software rendering.
ComputeThe CPU is the limit. The evaluation machine had 22 GB RAM and 16 threads.

4.2 Step 1: install ROS 2 Jazzy

Add the ROS 2 apt repository and install Jazzy by following the official guide: docs.ros.org/en/jazzy/Installation/Ubuntu-Install-Debs.html. The installer in step 2 stops if /opt/ros/jazzy is missing.

4.3 Step 2: run the installer

cd ~/Swachh/Navigation/Simulation/scripts
./setup_machine.sh --dry-run      # shows every change, changes nothing
./setup_machine.sh                # asks before each apt install
source ~/.bashrc
./preflight.sh                    # read-only; every line should say PASS

What setup_machine.sh does, in order:

  1. Detects the platform (native Ubuntu or WSL2) and the GPU.
  2. Installs missing apt packages: ros-jazzy-desktop, ros-jazzy-ros-gz, ros-jazzy-gz-ros2-control, ros-jazzy-ros2-control, ros-jazzy-ros2-controllers, ros-jazzy-navigation2, ros-jazzy-nav2-bringup, ros-jazzy-rtabmap-ros, ros-jazzy-depthimage-to-laserscan, ros-jazzy-topic-tools, ros-jazzy-rmw-cyclonedds-cpp, ros-jazzy-spatio-temporal-voxel-layer, python3-psutil, python3-scipy, python3-matplotlib, python3-pil, python3-yaml, python3-pytest, mesa-utils, python3-colcon-common-extensions, python3-rosdep.
  3. Sets the DDS socket buffers to 32 MB in /etc/sysctl.d/90-ros2-dds.conf. On WSL2 it also re-applies them at boot through /etc/wsl.conf.
  4. Adds the ROS, workspace and CycloneDDS lines to ~/.bashrc.
  5. Runs rosdep for the workspace dependencies.
  6. Builds the workspace with colcon build --symlink-install.
  7. Runs the evaluation-harness unit tests.

4.4 Alternative: build by hand

cd ~/Swachh/Navigation/Simulation/vacuum_ws
source /opt/ros/jazzy/setup.bash
rosdep install --from-paths src --ignore-src -r -y
colcon build --symlink-install
source install/setup.bash
Required DDS setting. If you build by hand, also set net.core.rmem_max=33554432 (as the installer does). Without it, SLAM silently receives no camera images.

4.5 In every new terminal

source /opt/ros/jazzy/setup.bash
source ~/Swachh/Navigation/Simulation/vacuum_ws/install/setup.bash
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
export CYCLONEDDS_URI=file://$HOME/Swachh/Navigation/cyclone_dds.xml
export ROS_DOMAIN_ID=0
# over SSH with no display, also:
export VACUUM_GZ_HEADLESS_RENDERING=1

If you ran setup_machine.sh, the first four lines are already in ~/.bashrc.

4.6 Verify the installation

# readiness check
bash ~/Swachh/Navigation/Simulation/scripts/preflight.sh
# evaluation harness unit tests
cd ~/Swachh/Navigation/Simulation/vacuum_ws/src/vacuum_eval && python3 -m pytest test -q

4.7 Run it

# 1. Gazebo + robot + controllers
ros2 launch vacuum_bringup sim.launch.py world:=office
# 2. SLAM on top (second terminal)
ros2 launch vacuum_slam slam.launch.py environment:=office use_rviz:=false
# 3. Autonomous frontier exploration (full stack: SLAM + frontier explorer + Nav2)
ros2 launch vacuum_exploration exploration.launch.py environment:=office
# 4. Navigation on a saved map (after sim.launch.py with use_sim_time:=true)
ros2 launch vacuum_nav2 nav2_localization.launch.py map_path:=$HOME/maps/stage5/office.yaml environment:=office

Save a map while the simulation runs: ros2 run nav2_map_server map_saver_cli -f ~/maps/stage5/office.

Worlds: apartment, cluttered_room, corridor, empty_room, empty_world, maze_dead_ends, multi_room_loop, office, symmetric_hall, two_rooms_door, plus obstacle-avoidance scenarios with the avoid_ prefix (for example avoid_u_trap, avoid_dynamic_sudden).

4.8 One-command demos

The scripts in ~/Swachh/demo set up ROS and DDS themselves. Press Ctrl+C once to stop everything a script started. Run one simulation at a time.

6. Part C: Manual mode (HMI and Arduino firmware)

6.1 Install the HMI (robot computer)

cd "$HOME/Swachh/Navigation/Manual mode/hmi"
bash scripts/setup.sh

setup.sh installs build-essential, cmake, pkg-config and libgtk-4-dev, installs arduino-cli if missing, and adds the user to the dialout group for serial access. Log out and back in (or reboot) afterwards so the group change takes effect.

6.2 Upload the firmware to the Arduino Uno

  1. Open Navigation/Manual mode/arduino/swacch_robot/swacch_robot.ino in the Arduino IDE.
  2. Select the board Arduino Uno and its serial port.
  3. Click Upload. The repository has no flashing script.

Wiring used by the firmware: motor PWM on pins 5 and 6, direction relays on pins 7 and 8.

6.3 Run

cd "$HOME/Swachh/Navigation/Manual mode/hmi"
bash scripts/run.sh

run.sh compiles the HMI on the first run (CMake), finds the Arduino on /dev/ttyUSB* or /dev/ttyACM* and starts the touchscreen interface. Without an Arduino connected, it starts without hardware.

6.4 Serial protocol (for testing)

SettingValue
Link115200 baud, newline-terminated text commands
MotionMOVE:FORWARD, MOVE:BACKWARD, MOVE:LEFT, MOVE:RIGHT, MOVE:STOP
SpeedSPEED:1 to SPEED:9
SafetyESTOP stops the motors and blocks motion until RESET
RepliesACK:<command> for each command, and STATUS: lines every second

7. Troubleshooting and known issues

Symptom or issueWhat to do
SLAM shows no map; no camera images arriveThe DDS socket buffer is too small. Set net.core.rmem_max=33554432 (section 4.3).
Gazebo is very slowNo GPU, so software rendering is in use. Use a machine with an NVIDIA GPU (driver 570+), and run only one or two simulations at a time.
A demo script refuses to startSomething from an earlier run is still running. Run ~/Swachh/demo/stop.sh.
Navigation/run_mapping.sh and save_map.sh failThey hard-code paths from another machine. Use the direct ros2 launch and map_saver_cli commands in section 4.7.
Navigation/stop.shForce-kills processes and deletes ~/.ros/rtabmap.db*. Do not use it during an evaluation run.
Navigation/start.sh opens no windowsIt needs the ptyxis terminal. Without it, use the direct commands in section 4.7.
Model files are tiny text filesGit LFS content was not fetched. Run git lfs install and git lfs pull.
HMI cannot open the serial portLog out and in after setup.sh so the dialout group applies; check the cable and port.
Some Navigation pytest vision tests failThey import camera code that moved to Object Detection/Camera/; these failures are stale tests, not a runtime fault.
