# 10 — Cleaning Efficiency and Swept-Area Coverage (#14, #1 cleaned flavour, A1, A2, A3)

There is no cleaning mechanism in the simulation. "Cleaning" is modelled **virtually from the ground-truth trajectory**: floor cells under the vacuum swath are marked as cleaned. Nothing in Gazebo changes.
Depends on: 00, 02 (`trajectory.csv`), 03 (GT grid, `a_clean`). Module: `vacuum_eval/metrics/coverage.py` (`swept_*` functions).

---

## 10.1 Swath model

- Swath width `W = swath_width_m` = **0.25 m** (placeholder = chassis width; replace when the real brush/nozzle width is known and record it in `run_meta.yaml`).
- Swath geometry: a line segment perpendicular to the robot heading, centred on `base_footprint` (offset 0 along the heading), length `W`. Endpoints in the robot frame: `(0, +W/2)` and `(0, −W/2)`.
- A cell is **swept** if its centre lies inside the region swept by the segment between two consecutive resampled poses: the polygon `[a_k, b_k, b_k+1, a_k+1]`, tested as the two triangles `[a_k, b_k, b_k+1]` and `[a_k, b_k+1, a_k+1]` (inclusive, tolerance 1e-9). *Decision 2026-10-20:* the first draft used "centre within half a cell diagonal of the segment"; implementation showed it widens a 0.25 m swath to ≈0.32 m (+23 % area), so it was replaced by this unbiased rule. Only cells in `a_clean` are counted.
- Rotation in place sweeps a disc of radius `W/2`; the resampling in §10.2 handles it.

## 10.2 Algorithm (exact)

Input: GT poses from `trajectory.csv` rows in the episode window (10 Hz).
1. **Resample** along the trajectory so consecutive poses differ by at most `0.02 m` in position **and** at most `0.05 rad` in yaw: for each consecutive pair, number of sub-steps `n = max(ceil(dist/0.02), ceil(|wrap(dyaw)|/0.05), 1)`; linearly interpolate position and yaw (shortest angular path).
2. For each consecutive pair of resampled poses, mark cells whose centre lies in the swept polygon (see §10.1); candidate cells from the polygon's bounding box; vectorised. Unit tests offset trajectories by a fraction of a cell because centres exactly on a swath edge are counted (inclusive test).
3. `swept` (bool grid) = union; also `visits` (uint16 grid) incremented **once per trajectory sample interval that touches the cell, counted per original 10 Hz sample step** (i.e. for each pair of consecutive original rows, take the union of cells touched by the sub-steps in that interval and add 1 to `visits` for each of those cells). This makes `visits` independent of the resampling density.
4. Restrict to `a_clean`.

## 10.3 Keys

| Key | Definition |
|---|---|
| `coverage_cleaned_pct` | `100 · |swept ∩ a_clean| / |a_clean|` at `episode_end_t` (**#1 cleaned flavour**) |
| `swept_area_m2` | `|swept ∩ a_clean| · res²` |
| `missed_area_m2` | `(|a_clean| − |swept ∩ a_clean|) · res²` (A3 cleaned side) |
| `overlap_ratio` | `Σ_c visits(c) over c ∈ swept∩a_clean  /  |swept ∩ a_clean|` ≥ 1 (A2; 1 = no re-cleaning) |
| `redundancy_pct` | `100 · (overlap_ratio − 1)` |
| `cleaned_m2_per_min` | `swept_area_m2 / (episode_sim_sec/60)` |
| `cleaned_m2_per_m` | `swept_area_m2 / distance_gt_m` |
| `cleaning_efficiency` | **`(coverage_cleaned_pct/100) / overlap_ratio`** — in [0,1]; 1 only if everything is cleaned exactly once |
| `cleaning_efficiency_time` | `coverage_cleaned_pct/100 / (episode_sim_sec / ref_time_s)` with `ref_time_s` = ideal time = `A_clean_m2 / (W · v_ref)` with `v_ref = 0.30 m/s` (Nav2 max speed). Not capped; reported as is (it can exceed 1 only if the true swath is wider than `W`) |

Interpretation to write in the paper: `cleaning_efficiency` penalises both missed area and re-cleaning; `cleaning_efficiency_time` additionally penalises slowness against a perfect boustrophedon at maximum speed. The two components (`coverage_cleaned_pct`, `overlap_ratio`) are always reported alongside the composite. If the user later prefers a different composite, only these formulas change.

## 10.4 Cleaned coverage over time (A1)

For time `t_ep` in steps of 5.0 s of episode time (and at `episode_end`): compute `coverage_cleaned_pct` using only trajectory rows with `t ≤ episode_start_t + t_ep` → columns in `coverage_curve.csv` (spec 03 §3.4). Keys `t_to_50_cleaned_s`, `t_to_80_cleaned_s`, `t_to_95_cleaned_s`, `coverage_cleaned_auc` (time-average of the curve, %).
Incremental implementation is allowed (process rows once and snapshot the count); it must equal the from-scratch result (unit test).

## 10.5 Visual output

`cleaned_heatmap.png` in the run dir: `visits` as colours over the GT outline (obstacles black, never-swept cleanable cells red, visits 1 green, ≥3 dark blue), plus the trajectory polyline. Generated by `compute_metrics`; matplotlib only.
